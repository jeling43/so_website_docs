Production Readiness Checklist

Release gate: Check, document, and sign off every required item before production deployment. Items marked Owner decision require an explicit decision from the project owner, captain, or IT administrator.

Download Markdown

1. Scope and approval

  • ☐ Confirm release scope, version, production owner, technical owner, and support contact.
  • ☐ Confirm this is an offline administrative statistics dashboard, not a case-management system.
  • ☐ Confirm Windows desktop is the production target; document macOS separately.
  • ☐ Confirm captain and secretary workflow review and written production approval.
  • ☐ Record known limitations, deferred features, and accepted risks.

2. Workbook and data accuracy

  • ☐ Test with the current official workbook and confirm all populated monthly sheets.
  • ☐ Confirm YEAR END is ignored as a monthly source and TOTAL is recalculated by the app.
  • ☐ Confirm headers come from row 1 beginning in column B and activities from column A.
  • ☐ Confirm blanks, true zeros, future blank months, formulas, and non-numeric cells behave as documented.
  • ☐ Confirm duplicate detective columns, duplicate activity rows, missing headers, and unexpected sheets are reported.
  • ☐ Confirm detective and activity aliases normalize correctly; unknown categories remain visible.
  • ☐ Confirm the original workbook is never modified.
  • ☐ Reconcile January through the latest populated month against Excel.
  • ☐ Reconcile division totals and at least three detectives across multiple months.
  • ☐ Save the import audit with workbook name, date, file hash, and reviewer initials.

3. Analytics calculations

  • ☐ Verify assigned, completed/closed, reports, warrants, callouts, agencies, scenes, and mileage totals.
  • ☐ Verify completion gap: assigned minus completed.
  • ☐ Verify recorded completion ratio and zero-denominator “Not available” behavior.
  • ☐ Verify month, year, detective, activity, all-month, and clear-filter behavior.
  • ☐ Verify averages, medians, assignment shares, previous-month comparisons, and missing-data handling.
  • ☐ Verify small-number changes do not create misleading alerts.
  • ☐ Confirm no overall detective performance score is displayed.
  • ☐ Confirm labels describe operational context, not quality, effectiveness, or misconduct.

4. User interface, HCI, and accessibility

  • ☐ Confirm the dashboard answers the captain’s key questions quickly.
  • ☐ Confirm reporting period, workbook name, refresh time, filters, and clear-filters action are visible.
  • ☐ Confirm Dashboard is division-wide and Detective Detail requires a selected detective.
  • ☐ Confirm charts precede detailed tables and all charts have legends, labels, and empty states.
  • ☐ Resize to minimum, typical, and wide desktop sizes; confirm no horizontal clipping or hidden cards.
  • ☐ Confirm tables scroll when necessary and card values remain readable.
  • ☐ Confirm color is not the only signal; verify contrast, focus states, keyboard navigation, and text scaling.
  • ☐ Confirm zero values differ from unavailable values.
  • ☐ Confirm analytical terms have explanations and loading/error/empty states are actionable.

5. Detective Detail and exports

  • ☐ Confirm selected detective, period, summary values, monthly totals, categories, and division comparison.
  • ☐ Confirm missing months, ties, and incomplete periods are explained.
  • ☐ Confirm PDF export uses current filters and includes source, date, summary, monthly comparison, categories, quality notes, and disclaimer.
  • ☐ Confirm PDF is readable on screen and paper, uses a safe filename, and handles failures.
  • ☐ Confirm CSV/PDF exports contain only filtered data and no new sensitive information.

6. Security and privacy

  • ☐ Confirm no network calls, telemetry, cloud storage, or workbook upload.
  • ☐ Confirm logs exclude workbook contents, case information, and sensitive identifiers.
  • ☐ Confirm workbook is read-only, extensions are validated, and malformed files are handled safely.
  • ☐ Confirm local settings, logs, exports, and temporary files use appropriate permissions.
  • ☐ Confirm workstation OS updates and endpoint protection.
  • ☐ Owner decision: define retention/deletion policy for reports, logs, and settings.
  • ☐ Owner decision: define who may access workbooks and generated reports.

7. Import resilience

  • ☐ Test missing, moved, deleted, wrong-extension, corrupted, blank, and no-month workbook files.
  • ☐ Test unexpected sheets, missing/duplicate headers, formulas, text in numeric cells, and blank numeric cells.
  • ☐ Test new activity categories and renamed detective headers.
  • ☐ Confirm valid data loads when one cell or sheet is invalid.

8. Automated testing

  • ☐ Run flutter test successfully.
  • ☐ Run flutter analyze; resolve errors and review production-relevant warnings.
  • ☐ Run importer, normalization, analytics, insight, filter, empty-state, PDF, and widget tests.
  • ☐ Run an integration test with a sanitized fixture workbook.
  • ☐ Test on a clean workstation with the actual production workbook copy.
  • ☐ Record Flutter, Dart, OS versions, test date, and results.

9. Windows packaging and deployment

  • ☐ Build and test flutter build windows --release on a clean Windows workstation.
  • ☐ Confirm runtime dependencies, startup, file picker, drag-and-drop, PDF save, and path persistence.
  • ☐ Confirm endpoint protection accepts the build.
  • ☐ Generate a versioned artifact and checksum.
  • ☐ Document installation, upgrade, rollback, and uninstall.
  • ☐ Owner decision: portable folder versus installer, signing certificate, and update process.

10. Logging, support, and documentation

  • ☐ Confirm startup, selection, import, validation, and export events are logged without sensitive data.
  • ☐ Confirm log limits/rotation, log location, support contact, and safe log-collection procedure.
  • ☐ Update README, installation/build instructions, supervisor guide, workbook replacement procedure, and data-quality guidance.
  • ☐ Document aliases, blanks/zeros, monthly versus year-to-date values, completion-ratio limitations, and report retention.
  • ☐ Provide a captain walkthrough and secretary workbook-maintenance checklist.

11. Production handoff

  • ☐ Create approved data, exports, and logs folders with correct permissions.
  • ☐ Back up the official workbook before first production import.
  • ☐ Record official filename, location, workbook hash, release version, and build checksum.
  • ☐ Import the workbook and obtain captain sign-off on displayed totals and latest populated month.
  • ☐ Confirm recovery from moved/deleted workbook and successful briefing export.
  • ☐ Define monthly refresh and workbook-template-change procedures.

12. Final go / no-go review

  • ☐ No blocking defects or unexplained total discrepancies.
  • ☐ No critical security, privacy, accessibility, or overflow defects.
  • ☐ Release build passes clean-workstation testing.
  • ☐ Production reconciliation, user guide, support contacts, and rollback build are ready.
  • ☐ Captain approval received.
  • ☐ IT/deployment approval received.
  • ☐ Go-live date and owner confirmed.
